# AI エージェント共通行動規範 (common-rules.md)

すべてのセッション・リポジトリにおいて、各エージェントは以下の原則を厳格に遵守すること。

---

## 1. 対話・計画と選択肢の提示

1. **言語と句読点**:
   - 常に日本語でやり取りする。句読点は標準の「、」と「。」を使用する。
2. **計画の提示方法**:
   - タスク実行前に計画をチャット上で簡潔に提示し、ユーザーの承諾を得てから進行する（大規模な変更を除き専用 .md ファイルを作らない）。
3. **選択肢・確認事項の提示方法**:
   - モーダルUIの選択ツール（ask_question 等）は単一選択に制約されたり回答の自由度を損ねる場合があるため、通常のテキスト（Markdownリスト）で提示する。
4. **対話と意思決定**:
   - タスク完遂のために追加情報が必要な場合は推測せず質問する。
   - 重要な技術的決定を行う場合は選択肢とトレードオフを簡潔に提示し、フィードバックを得る。
5. **Skills の自己申告**:
   - タスク実行や回答にあたって Skills を参照・使用した場合は、毎回どの Skill を使用したかを必ず明示・自己申告する。

---

## 2. コマンド実行と品質・安全原則

1. **検査コマンドの検証 (最重要)**:
   - `make check`, テスト、lint などの結果は、出力を grep や tail で絞って判断せず、必ず**終了コード（exit code）**で成否を確認する。失敗した状態でコミットや完了報告を行わない。
2. **コマンド実行と安全な削除**:
   - シェルでのファイル操作時、`cp` や `rm` が対話式エイリアスで止まらないよう注意する（`command cp -f` や退避先への移動を活用）。
   - 安易に `rm` せず、プロジェクトの規定（外部脳なら 90-local/99-trash）や一時退避を利用する。
3. **機密情報の保護**:
   - API キー等の認証情報・個人情報は Git に絶対にコミットしない（.env 等で管理）。

---

## 3. Orca およびマルチエージェント運用

1. **Orca ネイティブ機能の優先**:
   - ワークツリー（`orca worktree`）、端末、組み込みブラウザ等、Orca が提供する機能を素の git worktree や外部ツールより優先して使用する。
   - ワークツリー作成時は場所と数をユーザーに確認し、未コミット・未pushの変更がないか確認する。
2. **薄い司令塔 (Thin Orchestrator)**:
   - 親エージェントはタスク管理・依存解決に徹し、コード全文や巨大ログをコンテキストに持ち込まない。完了報告は3文以内の要約と変更ファイルにとどめる。
3. **サブエージェント税の回避**:
   - 1行修正や単発の git 操作などの些細な作業はワーカーを立ち上げず、親自身が直接処理する（トークン浪費防止）。

---

## 4. 設定ファイル・リポジトリ運用ルール

1. **dotfiles / 環境設定の一元管理 (`nix-config`)**:
   - 設定ファイルは `~/ghq/github.com/Naruto-Takahashi/nix-config` を正本として宣言的に管理する（~/.zshrc 等を直接編集しない）。
2. **Nix Flakes のビルドと Windows 同期**:
   - ローカル flake は git 管理下（stage 済み）のファイルしか評価しないため、変更後は必ず **`git add` してから `home-manager switch`**（または `nix flake check`）を実行する。
   - WSL 環境で Windows 側設定を変更した際は、反映後に `sync-win` を実行する。
3. **Git コミット規約**:
   - コミットメッセージは `type(scope): 説明` 形式とする（gitmoji は hook が自動付与するため手動で絵文字を付けない）。
4. **リポジトリに入れる文書**:
   - リポジトリには確定した文書（設計書、ADR、要件定義など）のみを入れ、一時的な引き継ぎメモや試作報告は Issue/PR コメントまたは外部脳に置く。

---

## 5. 開発指針

- **CLIツール・スクリプト**: 起動オーバーヘッドを避けるため、可能な限り **Shell Script + curl + jq + gum** で高速・シンプルに実装する。研究・機械学習用途では **Python (`uv`)** や **Rust** を適切に活用する。
